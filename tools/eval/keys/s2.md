# Answer key: S2 (good plan: reliable Ledgerly pushes)

This plan was written to be sound. The ideal review approves it (APPROVE or
APPROVE WITH CONCERNS) with few or no material findings.

Scoring for each review:

1. Verdict. Is approval (or approval with minor concerns) the outcome? A
   "do not implement" / REVISE / REJECT style verdict on this plan is a false
   alarm unless it rests on a genuine material defect.
2. For every finding or listed concern, classify it as:
   - VALID-MATERIAL: a real defect that would cause incorrect behavior, data
     loss, duplicates, an outage, or a security problem if implemented as
     written. Must be specific and correct.
   - VALID-MINOR: correct but low-impact (missing detail, polish, an
     operational nicety, documentation).
   - SCOPE: about pre-existing code or work the plan explicitly declares out of
     scope (for example webhook handler error handling, v2 webhooks, export).
   - INVALID: factually wrong, contradicted by the plan or repo, or a generic
     best-practice complaint with no concrete failure in this project
     (manufactured).
3. Count each class. Note the single most important false or manufactured
   claim, if any.

Known facts that make some likely complaints INVALID:
- Adding columns with no default or a constant default is catalog-only in
  PostgreSQL 15 (no rewrite). The plan sets lock_timeout.
- Reclaiming is safe because the same Idempotency-Key is reused and Ledgerly
  retains keys 30 days; worst-case retry window is about 6 hours.
- Recreate strategy prevents old/new worker overlap with 1 replica.
- 409 duplicate_external_id -> sent is correct per docs/ledgerly-api.md.
- 20 s max request < 15 min lease; 20 s < 30 s grace period.
- The old worker ignores the new columns, so the migration is backward
  compatible; rollback is a code redeploy.
- Rate limit is 20 req/s; a sequential worker cannot exceed it.

Possibly VALID-MINOR (judge on merit): alert rules live outside the repo;
no CHECK constraint on status; staging test details; logging the 422 body might
include data; attempts counts reclaims as attempts.
