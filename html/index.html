The useful kind of difficult

Not another agreeable assistant.

GrumpyDev makes engineering-plan review easier and more effective. A more skeptical agent catches weak assumptions before they become code.

01 / SURVEY

Learn the ground truth

Survey the repository, its stack, conventions, constraints, supported runtimes, and deployment setup. Record the result in a human-owned .grump file.

02 / SPECIALIZE

Install skills for your stack

Add focused skills for the technologies the project actually uses - only with permission.

03 / CHALLENGE

Review the plan, not the vibes

Test assumptions against evidence, explain what can fail and why it matters, and end with a verdict engineers can act on.

Context that survives the chat

The project gets a constitution.

The survey produces a plain Markdown file called .grump. Humans own it. Agents read it. Decisions stop evaporating between sessions.

Read the file specification ->
.grumpHUMAN-OWNED 
# Project doctrine

## Non-negotiable constraints
- [CON-001] Preserve idempotency for background job submission.
- [CON-002] No production schema changes without rollback.

## Accepted tradeoffs
- [ACC-004] Batch processing latency up to 15 minutes is acceptable.

## Evidence expectations
- Link every review finding to repository evidence.
