Plan and code review for AI coding agents

Your plan has problems. GrumpyDev keeps track of them.

Ask your coding agent to Grump this plan and it reviews like a skeptical senior engineer, gives a verdict, and records every issue in a ledger. Revise the plan, Grump it again, and each issue comes back marked fixed, still open, or regressed.

What it does

Your agent reviews against the code and keeps a record.

01 / REVIEW

A review that reads the code

Your agent checks the plan or diff against the actual code, config and deploy files: wrong claims, old and new versions running together, retries and partial failure, units and time zones, code in the wrong place, and steps the plan leaves undecided. Every finding says where, what happens, and the fix.

02 / TRACK

Issues tracked across sessions

Each issue gets an ID and a "closes when" condition in .grumpydev/reviews/. The next review, in any session, marks it RESOLVED, OPEN or REGRESSED, and Grump status lists what is still open across every plan.

03 / REMEMBER

Decisions written down once

.grump records what production really runs, what cannot change, what was decided and which debt is accepted. GrumpyDev copies the rules into CLAUDE.md, AGENTS.md and the other agent files, so the agent writing code knows them too.

REVIEW VERDICTS
APPROVE APPROVE WITH CONCERNS REVISE REJECT NEEDS INFO
The second review

It remembers what it said last time.

A fresh session reads the ledger, rechecks every earlier issue against the revised plan, and only counts a fix it can see in the plan or code. A claim that something was fixed is not evidence.

Why not just ask your agent?

You can, and for many reviews it works.

We ran the same reviews with GrumpyDev and with a well-written "act like a skeptical senior engineer" prompt, on Claude Sonnet and Haiku, and had them graded blind. On an ordinary plan or diff, both found about the same problems.

GrumpyDev found more when the answer depended on the project: what production really runs, which module owns a rule, and bugs already in the files a plan touches. On one plan that edited files with seven existing problems, Sonnet with GrumpyDev reported about six and the plain prompt about two. A GrumpyDev review used 1.1 to 1.6 times the tokens. Full results.

PROMPTThe same review instructions and verdicts every time, instead of whatever was typed that day.
LEDGERIssues keep their IDs and status across revisions and sessions. A plain prompt in a new chat starts from nothing.
RULESPins like "production runs PHP 7.4" live in one file that every review and every coding agent reads.
