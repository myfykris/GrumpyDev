# NestJS survey contribution

## Applies when

Apply this contribution when the project uses or materially depends on NestJS.

## Inspect

- Establish the exact Node.js, NestJS, TypeScript, adapter, transport, and
  deployment versions.

## Ask when unresolved

- Which Node.js, NestJS, TypeScript, HTTP adapter, transport, and package
  versions apply?

- How do module boundaries, provider scopes, guards, pipes, interceptors,
  validation, and shutdown interact?

- Which runtime or deployment differences materially change future reviews:
  Node.js and adapter, Express or Fastify behavior, process and worker model,
  proxy, transports, queues, state, shutdown hooks, and deployment artifact?

## Record

Map durable NestJS version and behavior requirements to `Requirements` or
`Constraints`, lifecycle and deployment facts to `Runtime and deployment`, and
material gaps to `Unknowns`.
