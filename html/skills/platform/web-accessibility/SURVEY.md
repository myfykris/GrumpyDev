# Web accessibility survey contribution

## Applies when

Apply this contribution when the project includes user-facing web interfaces or rendered
web content.

## Inspect

- Read rendered HTML, interaction states, forms, routing, CSS, content, error
  handling, automated checks, and manual keyboard and screen-reader results.

## Ask when unresolved

- Which accessibility targets, assistive technologies, and keyboard, zoom,
  reduced-motion, and high-contrast needs must the project support?

- How are focus, accessible names, errors, live updates, and semantic
  relationships verified?

## Record

Map durable Web accessibility requirements and constraints to the matching
doctrine sections, runtime facts to `Runtime and deployment`, and material gaps
to `Unknowns`.
