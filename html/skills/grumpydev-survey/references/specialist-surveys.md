# Specialist survey routing

Load this reference during initial setup, after a specialist is newly
installed, or during an explicit re-survey that includes specialist context.

Use installed complete GrumpyDev specialist skills only. Their immediate
directory and frontmatter names must match and begin with `gd-`, and their
descriptions must contain the explicit-only GrumpyDev activation boundary. Do
not load an unrelated skill or a malformed `gd-` collision. Do not fetch another
skill because a survey mentions a related technology. Read an installed
specialist's `SURVEY.md` when project evidence does not make it clearly
inapplicable. Treat its questions as candidates, not as a questionnaire that
must be completed.

Pool candidates from every applicable specialist before numbering. Remove any
candidate already answered by inspected evidence, `.grump`, available context,
or an explicit user statement. Merge candidates that resolve the same version,
runtime, deployment, ownership, compatibility, or operating decision. A
specialist may contribute zero questions.

Record durable technology facts in the applicable doctrine section. Put only
explicit project-specific exclusions under `## Specialist exceptions`, with
the evidence that makes the installed specialist inapplicable. Do not create a
catalog inventory or status row for every installed or uninstalled skill. Use
`UNK-###` only when missing specialist context could materially change a future
review. Ordinary reviews load specialist `SKILL.md` files, never `SURVEY.md`.
