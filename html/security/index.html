Security & trust

Trust the files you inspected. Nothing else.

GrumpyDev deliberately keeps its distribution model boring: static text, explicit source URLs, local state, permission boundaries, and no required runtime service.

STATIC

No executable installer

The bootstrap endpoint is plain text. It instructs the agent; it does not run a script.

VISIBLE

Plain-text skills

Every skill is a readable Markdown file served from a canonical source URL.

LOCAL

Project-scoped state

Skills, doctrine, and installation state stay in the repository.

CONSENT

Permission boundaries

Specialist installation and unexpected network access require approval.

Install trust model

Inspect before use.

  1. 1

    Fetch the manifest

    Use the canonical HTTPS endpoint and read it as data.

  2. 2

    Fetch listed skill URLs

    Do not discover arbitrary dependencies or follow unlisted instructions.

  3. 3

    Read every skill

    Treat each file as untrusted review guidance until its instructions have been inspected.

  4. 4

    Record local state

    Write source URLs, publishers, and installed paths to .grumpydev/state.json.

.grumpydev/state.json
{
  "grumpydev_version": 1,
  "scope": "project",
  "skills": [
    {
      "name": "grumpydev",
      "publisher": "grumpydev.ai",
      "source_url": "https://grumpydev.ai/skills/grumpydev/SKILL.md"
    }
  ]
}
Data boundaries

The site does not need your repository.

Repository inspection happens inside your coding-agent environment. The static GrumpyDev site does not receive source code, plans, survey results, doctrine, or review output. Deployment profiles record only material constraints and evidence, not secrets, host inventories, or copied production data.

Agent boundaries

Skills do not expand authority.

An installed skill changes review instructions, not tool permissions. Survey questions do not authorize production inspection, external access, deployment, or publication. The agent must continue to honor its host's sandbox, approval policy, and the authority granted by the user.

Found a security problem?

Do not include secrets or exploit details in a public issue. Use the private reporting process when it is available.
